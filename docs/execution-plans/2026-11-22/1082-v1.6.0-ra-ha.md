## 1. Intent

Deliver `v1.6.0` as a self-hosted, single-principal, service-based distributed
edge research platform. It never trades. It turns historical candles into
reproducible evidence about whether a rule-based alpha has an edge.

The platform adds reusable research artifacts (RA), a genuinely available
runtime with one Patroni cluster and four logical databases (HA), and the GA
release gate that keeps docs, code, tests, commands and verification evidence
consistent.

The browser and CLI remain thin clients. They connect to `https://quantrule.dev`
and speak `quantrule.api/v1`. The 49 pre-RA commands and screens remain
compatible; the current surface is 61 commands, and pack/signal management is
additive.

## 3. Scope

Included:

- Model artifact as the upstream input, plus four RA objects: strategy pack,
  signal artifact, portfolio policy pack, execution-simulation pack.
- Seventh stateless `strategy` service for signal-mode packs.
- `quantrule.run/v5`; v3 and v4 remain readable.
- Pack registry, lineage, retention, freeze and retire.
- Additive pack/signal commands, browser Packs surface and run detail.
- Four logical databases in one Patroni cluster with per-service roles.
- Cross-DB outbox, idempotency, reconciliation and tombstones.
- RabbitMQ quorum queues, evidence leader, data and simulation concurrency.
- Swarm, Traefik, Patroni/etcd/HAProxy, MinIO, observability, backup/DR.
- `quantrule.deploy/v3`; `quantrule.dev`; 443-only ingress.
- The five test tiers (`fast`, `composed`, `multi-host`, `parity`, `ha`); the DR,
  security, soak and upgrade checks are HA/lab phases, not new tier names.
- Manual, architecture, runbooks, support matrix and release records.

Excluded:

- Live trading, broker connectivity, OMS, real-time risk and regulatory scope.
- Desktop shell, Tauri, installers, OS packages and desktop release assets.
- Python, Kubernetes, accounts, tenancy and user authentication.
- Autoscaling, four separate PostgreSQL clusters and per-bar network folds.
- A separate research service; research stays in evidence.
- Changing the meaning of any of the 49 pre-RA commands or screens.

## 4. Assumptions and uncertainty

- Docker Swarm is the v1 orchestrator; stateful members are pinned, not freely
  rescheduled.
- The four databases share one Patroni cluster; heavy evidence work is bounded by
  role limits and may later justify a separate evidence cluster.
- Signal mode uses a deterministic reference position and excludes giveback
  unless candles become an explicit input.
- The single-host three-VM lab proves simulated node failure, not physical host,
  AZ, power or disk-controller failure.
- The human can provide three physical hosts for the final real-topology claim,
  or accepts the simulated evidence boundary in the release note.
- The browser/CLI contract stays frozen; failover is a reconnect, not a new
  command or screen.
- The 2026-11-25 re-baseline and the 46-leaf board are the plan of record; the
  original 65-ID plan is a source, not a second authority.
- Internal TLS is implemented for PostgreSQL, RabbitMQ and MinIO. mTLS remains
  deferred with the residual risk recorded in ADR-1108.

## 12. Risks and recovery

| Risk | Control |
|---|---|
| Scope explosion | Phase gates, one PR per leaf, exclusive file ownership |
| Two plan trees | §8.1 mapping; the 46-leaf board is the only plan of record |
| Board drift | Reconcile the 10 merged items, #1085 and the parent counts |
| Signal semantics unclear | ADR-RA and Quant Validator before RA-007; Done |
| Cross-DB inconsistency | Outbox, idempotency, reconciliation, tombstones, drills |
| Patroni split-brain | Quorum, watchdog, strict sync, fencing, failover tests |
| Swarm stateful rescheduling | Pin stateful units; document manual recovery |
| One-cluster resource contention | Role limits, statement timeouts, split evidence later |
| Single-host overclaim | Evidence labels; real-lab verification or accepted risk |
| Image distribution gap | Private registry or documented load procedure |
| mTLS deferred | ADR-1108 records the residual risk; stateful TLS is implemented |
| Digest mismatch or partial publish | Stop; fix before release |

Recovery: previous image digest, previous stack and previous databases remain
available until the new stack passes. Migrations are forward-only. DNS returns
to the old ingress on failure. The release note records rollback evidence.

## 13. Stop conditions

Stop if the human does not approve an ADR, schema or topology; if the 46-leaf
board and the plan diverge again; if a failure test produces a digest mismatch
or partial publish; if cross-database consistency fails; if security finds a
Critical issue; if the failure matrix cannot pass; or if a change requires
live-trading scope.

## 14. Closure

The plan is `Verified` only when every row is `Pass` or `Accepted risk`, the
`v1.5.3` pre-GA tag exists, the `v1.6.0` release note is published, the board is
consistent, and merged worktrees and branches are removed.
