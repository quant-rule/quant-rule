- Claim type: workflow, documentation, and tooling plus one behavior-neutral
  refactor cycle. No model, strategy, execution, portfolio, or analytics
  behavior change.

## 1. Intent

Add a bounded, human-gated Refactor Workflow that improves structure without
changing observable behavior. It must cover code, tests, documentation, tools,
and repository layout; keep coupling low and cohesion high; keep names readable
and consistent; and verify every cycle with independent evidence.

The workflow answers one question: **is the program structured so the next
correct change is cheap, local, and provable?**

## 4. Assumptions and uncertainty

- The existing Rust and documentation gates prove behavior preservation for a
  move-only refactor; the assessment records the baseline so the verifier can
  compare.
- The first cycle can be chosen from the assessment as a leaf seam with strong
  golden coverage. If no such seam exists, the loop stops at the assessment.
- The structural checker can enforce only rules that pass today. Any existing
  violation is either fixed in this work item or downgraded to advisory.
- The architecture baseline is refreshed from the structural report rather than
  hand-counted.

## 5. Decisions

| Decision | Choice | Consequence |
|---|---|---|
| Workflow placement | Engineering workflow with four specialized roles | No fifth decision authority; existing approval gates stay |
| Assessment kind | New `docs/refactors/` kind | Refactor findings do not inherit audit severity or status semantics |
| Loop | Bounded campaign; default 3 cycles, hard stop 5 | Prevents endless refactoring |
| Enforcement | Hard rules that pass today plus an advisory scorecard | No mass cleanup and no failing gate on the current tree |
| Phase A packaging | One PR for the workflow, roles, indexes, and gate | Shared review surface; A1-A3 remain separate acceptance issues |
| Phase B packaging | Assessment, cycle, and closure as separate PRs | Each deliverable is independently reviewable |
| Naming | Domain names, one term per concept, no catch-all modules | Keeps code, docs, issues, and PRs understandable |

## 6. Acceptance criteria

- The workflow contract, assessment format, and roles exist and are indexed.
- AGENTS references the workflow in sections 1, 2, 5, 8, 9, 10, 11, 13, and 14
  without contradiction.
- `tools/check_structure.py` passes on the current tree and runs in CI.
- The architecture baseline is reconciled or marked as generated by the
  structural report.
- The first assessment records a baseline and `REF-` findings with reproducible
  evidence.
- One cycle plan is approved with a named seam, metric target, and traceability.
- One behavior-neutral refactor PR passes full equivalence gates.
- The Refactor Verifier records observed results and moves the finding to
  `Verified`, or returns it for remediation.
- The loop decision is recorded and the parent/sub-issues are closed.

## 9. Risks and recovery

| Risk | Mitigation | Recovery |
|---|---|---|
| AGENTS contradictions | Additive edits; one source of truth; link and term gates | Revert the integration commit and re-plan |
| Checker too strict | Only rules that pass today; advisory scorecard; no ratchet | Downgrade the rule in an approved PR |
| Endless refactoring | Campaign cap; one seam per PR; no metric improvement means close | Stop the loop |
| Behavior drift | Equivalence contract; fixture and output hashes; independent verifier | Return the finding to remediation |
| Layout checker brittleness | Parse `docs/README.md`; objective rules only; historical exceptions advisory | Move the rule to advisory |
| Pilot too large | Assessment selects a leaf seam with strong coverage | Stop and re-plan |

Rollback is the branch. There is no migration or external state. If a gate
misbehaves, disable it in a separate approved change; never weaken a test.

## 10. Stop conditions

- The workflow requires a behavior change to be useful.
- The plan needs a new dependency, CI service, or architecture decision.
- A module-boundary change is consequential and not covered by the plan.
- Existing gates fail for unrelated reasons.
- The checker cannot pass without a mass cleanup.
- The first assessment finds no High or Medium finding. That is a valid stop.
