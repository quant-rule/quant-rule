# AI Transparency — Run v5 End-to-End

- Date: 2026-11-26 (UTC)
- Work item: `REM-RA-005` ([#1208](https://github.com/quant-rule/quant-rule/issues/1208))
- Tool: OpenCode coding agent; model identifier reported by the harness is
  `DeepSeek V4.1 Flash 1017`.
- Claim type: Behaviour Claim; no model, strategy, signal, or edge claim.

## 1. Intent and boundary

Prove a v5 run from submission through the fold and a recorded digest, keep the
v4 regression, refuse to publish a failed run, and compare one worker with two.
The work also fixed two production gaps the test exposed. This change does not
claim a composed, lab, or release run; the composed v5 script is wired but was
not executed on the laptop.

## 2. Implemented

- A worker v5 test builds a real v5 config around the existing v4 model bundle,
  submits it with its lineage, resolves the three packs, folds, reads every
  published artifact back by hash, and records the digest.
- A second worker case omits the strategy pack: the run fails closed with no
  digest, no artifact, and no run manifest.
- A third worker case runs one worker and two concurrent workers over the same
  v5 input and compares the digest; the model is called once.
- `crates/quantrule-app/tests/run_v5_e2e.rs` runs the same fold twice through
  `AppService` and compares a checked-in golden digest; the app digest equals
  the worker digest.
- `PortfolioRequest::replay` gained `replay_resolved`; the shared stage loop now
  passes the resolved `RunConfig` instead of a path, so a v5 fold no longer
  re-reads `run.json` and loses its references.
- The model service resolves the bundle's pack and signal references once and
  calls `RunConfig::load_with`, so a full v5 run without a promoted model
  artifact no longer fails at model compute.
- `tools/verify.sh` registers the three v5 fixture packs, rewrites the run
  references, and `tools/composed.sh` runs the v4 and v5 parity suites.

## 4. Learning

- The worker test's fake model bundle hid a real gap: the model service still
  used the v5-rejecting loader. A production-shaped E2E must exercise the
  service that builds the bundle, not only the one that consumes it.
- The portfolio stage re-read the run path even after the worker resolved the
  config, which made the v5 fold fail after a successful strategy and execution
  stage. Passing the resolved config through the stage loop is the correct seam.
- A promoted model artifact and a full model compute are different paths. The
  composed fixture uses the full path; the worker tests cover both the
  no-artifact path and the artifact-reference shape.
- The app fold and the worker fold produce the same digest when they share the
  same model bundle, which is the parity the run contract claims.
