## Intent and boundary

S2 implements the first strategy on the S1 type boundary: the axis-agreement
rule over the published Direction, Momentum force, and Structure score. It
adds `AxisAgreementStrategy`, which enters long or short when all three
readings agree beyond the configured thresholds and exits when that agreement
no longer holds.

The strategy is pure. It reads one closed bar at a time and its own open
position; it performs no I/O, reads no clock, uses no randomness, and keeps no
global state. It creates no order, fill, position, equity, or P&L record. Those
belong to the execution and portfolio work items. The change adds no shell
command and changes no model output.

## Decisions and learning

- **Unavailable holds, neutral exits.** `Agreement::classify` returns `None`
  when a reading is missing or non-finite. The strategy treats that as no
  evidence and holds an open position; it exits only on a measured `Neutral` or
  the opposite agreement. Treating `None` as agreement loss would replace a
  missing measurement with a negative one, which the model contract forbids.
  This is the first-run default and is stated in the module docs.
- **A wrong timeframe is ignored.** The strategy is configured for one
  timeframe. A bar from another timeframe produces `Hold` instead of being
  classified, so a misconfigured runner cannot trade a series the rule was not
  defined for. S3 must feed the configured timeframe.
- **No same-bar reversal.** An opposite agreement closes the open position; the
  next bar may open the opposite position. Reversing on one bar would make one
  bar carry two decisions and would complicate the causal accounting.
- **No end-of-data exit.** The strategy has no notion of the end of a series.
  If the data ends while a position is open, the position remains open; the
  portfolio work item defines how a final position is valued or closed. This
  matches S1's deferral.
- **The fixture is hand-derived.** The expected decisions were written from the
  rule, not captured from the implementation, so the golden test fails if the
  rule changes silently.
- **Rejected:** a strategy-level `run` helper that returns all records. S3 can
  iterate the bars and call `on_bar`; a second iteration API would duplicate
  the trait and pre-empt the runner design.
- **Rejected:** optimizing the thresholds or adding a second strategy. The plan
  fixes one configurable rule for the first run.
