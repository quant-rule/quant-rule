- **Learning:**
  - **The three loose ends were one kind of defect wearing three faces.** Each was a record that stated something the code or the board did not do: the ADR said it was proposed, section 4 said the tests live where they cannot live, and the script said a merged pull request is `Done` while writing `Todo`. A repository's correctness is not only in its code but in whether its records agree with it, and the audit that found the third one — comparing every board item against the state of the content it holds — is worth more than the fix.
  - **The board's own automation had not marked the merged pull requests `Done`,** which is why the script's silence went unnoticed for twelve merges. The script's header documented the intended behaviour, the code did not implement it, and the board was read as a task list rather than as a record of what had happened. A rule that is written in a comment is not a rule that is running.
  - **Rejected:** extending the script to sweep the whole board on every run. The workflow triggers on every issue and pull request event, so the board converges on its own once the defect is fixed, and the eleven historical items are a one-off correction. A sweep is a larger change to a script that works, and it would rewrite fields the board's own workflows own.
  - **Rejected:** correcting the eleven items by hand through the API. One code path for the history and the future is worth more than a one-off save, and the script is idempotent, so the run is safe to repeat.
  - **Corrected:** the script's header claimed that it "writes only what differs". It writes every field on every run; what it guarantees is that the board it leaves behind differs only where it must. The claim was softened to the true one, and the correction is in the same change that touched the header.
  - **Corrected:** the script's header also claimed that the board's built-in workflows write the `Status` field, including for a merged pull request. The audit showed eleven merged pull requests at `Todo`, so the header now says what the automation does and what this script does.
  - **Rejected:** leaving section 4's sentence to the data engine's change, as the data engine's plan proposed. The sentence is false against the layout the plan itself commits to, and an implementer reading section 4 before the plan would be told to put the integration tests where they are never compiled. The correction is one line, and the plan's decision B3 now records that it was made ahead of the data engine's change.
  - The ADR's `Accepted` status rests on an instruction rather than on a quotation, and the record says so, with the date. A status that says what it rests on is honest; a status that implies more than it has is not.
  - **Observed, not fixed:** the script sets a leaf's `Status` from the content's own state, so an open pull request's board item reads `Todo` whatever the agent set it to, and the next event resets it. This is the pre-existing division of ownership between the agent and the workflow, and this change did not touch it. It is recorded here because the same script now sets `Done` for a merged pull request, which makes the reset visible: the status of a pull request item is a function of whether the pull request is open, not of whether its work is in flight.
