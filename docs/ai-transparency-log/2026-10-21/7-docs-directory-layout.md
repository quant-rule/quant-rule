- **Learning:**
  - The kind-first layout is not a cosmetic preference. The old tree started with the date, so a reader who wanted "the execution plans" had to already know the date to find them, and a reader who wanted "the transparency log" had to know that the log was a file inside a date folder rather than a folder of its own. Putting the kind first turns the tree into an index of what exists, and the date becomes the detail.
  - The UTC decision was not free. It moved the shell-application work item into a different folder than the local date would have put it in, and it required a date field in three files to change value. The alternative was a permanent contradiction with section 12, which already requires UTC for all timestamps, and a folder name that meant different things depending on where the author was sitting. Two work items stay in 2026-10-20 and one moves to 2026-10-21, which is the smallest honest outcome.
  - Splitting the log exposes a design fact the single file had hidden: the log had three entries, each written for a different work item, and they shared a file only because the file was a natural container for a date. Making the file the unit of the work item rather than the date means the log and the plans are now siblings, discoverable by the same base name, and it removes the append-only growth that made the single file a poor thing to navigate.
  - The verification scripts needed two rounds. The first version of the split-integrity check compared whole entry bodies and failed, because the date field had been edited on purpose; the check now isolates the date field and asserts the rest is verbatim. The first version of the path check reported nineteen apparent missing paths that were mostly branch names, a rejected alternative, a placeholder, and the old layout quoted in this change's own plan. The pattern was narrowed to navigational paths of the form `docs/<kind>/<date>/<file>.md`. A check that flags everything is a check nobody reads; narrowing it to what the claim actually is makes the result meaningful.
  - Git records the three plan moves as renames but records the log as one deletion and three additions, because a file that becomes three files is not a rename. The history of the original log therefore does not follow the first entry. This is a real, if small, cost of the split, and it was accepted rather than worked around: a synthetic rename would have misrepresented what happened.
  - `docs/adr/` is named in `AGENTS.md` and does not exist, and it cannot exist while it is empty, because Git does not track empty directories. The wording was kept as a future location rather than papered over, and the path-existence check treats it as the one path that is named before it exists.

All four were corrected. The last one is the same fault this repository has already corrected twice, which is why the claim in the previous entry about a commit that could not yet exist should have been written as a statement about the procedure rather than as a claim about a fact.
