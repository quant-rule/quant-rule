- **Learning:**
  - **The independent review pass earned its cost again, and its findings were of two kinds.** The first kind was missing work: the contract, which `AGENTS.md` now names as the authoritative document the implementation follows, had been written from the specification and simply did not contain the eleven decisions the plan claimed to have made. A document that delegates its normative definitions to an execution plan is not a contract. The second kind was false statements about verification: the log said the diff had been reviewed "before the commit" when no commit existed, said two cells had been corrected when a third was missed, said a mitigation was applied to the issue bodies when it was not, and counted eleven rows in a table of fourteen. Each of those is the same error the earlier entries in this repository record — a record written about work that had not happened — and the fix in each case was to make the statement match what was done, not to soften it.
  - The specification and the repository's own rules contradicted each other, and the contradiction was the most valuable thing in the task. `AGENTS.md` section 2 and issue #14 both made an indicator the owner of an axis, while the specification made indicators shared inputs with per-axis roles. Nothing could have been implemented until that was resolved, which is why the documentation change precedes any code, and why the plan's first work item is the reading layer with a role registry rather than the "indicator abstraction" issue #14 originally asked for.
  - **The specification's open points were the real design work.** Eleven points had no answer in the text, and two of them changed what the model publishes. The sharpest was the leg lifecycle: a pivot is knowable only when its right-side bars have closed, so a leg created from a confirmed pivot is confirmed the instant it exists, and `lifecycle_code` 0 and unavailable-reason 6 would have been dead vocabulary. Deriving that a leg must be created from a left-side candidate pivot, so that "forming" is a reachable state, was the single most consequential inference in the plan, and it is recorded as A2 with the alternative stated.
  - The four axes do not aggregate the same way, and writing that down early prevented a whole class of later error: a mean is legal for Direction and Momentum because they use one signed scale on every timeframe, and it is illegal for Structure and Progression, whose codes are ordinal. The aggregation work item's acceptance criteria say so in the imperative, because a sub-issue author reading only that issue would otherwise reach for a mean.
  - **Rejected:** a new umbrella issue for the metrics layer. The human chose sub-issues of #14, and the board's `Parent issue` and `Sub-issues progress` fields made that work natively rather than by convention.
  - **Rejected:** writing the crate names into `AGENTS.md` section 2 in this change. Section 2 says no crate name is assumed before the workspace exists and that the names are recorded in the same change that introduces it, so the names are decided in the ADR and written into section 2 by the data engine's own change. Writing them now would have contradicted the file's own rule.
  - **Rejected:** an unbounded set of level references for Level events, which the specification permits by reading "confirmed minor/major swing levels" literally. It would make the event stream and the event store grow without limit, which the new bounded-retention rule in section 12 forbids. The bounded set of A6 is also the set the clustering uses, so the two agree on what a level is.
  - **Rejected:** giving the model a composite score, and letting events adjust axis values. Both were available and both were refused, because the divergence and the RSI values behind it are the same evidence twice. The anti-double-counting rules are written as named sub-issue acceptance criteria, so the refusal is testable rather than a matter of taste.
