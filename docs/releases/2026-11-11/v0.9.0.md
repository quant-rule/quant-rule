## Scope

The first Tauri Platform release. QuantRule is now a local-first Linux desktop
workstation with a shared application service, a SQLite research memory, and a
static distribution page. The shell remains the headless surface.

Included:

- `quantrule.run/v3`; the policy/prop-firm layer is removed and `run check`
  replaces `policy check`. Portfolio capital, sizing, costs, drawdown, leverage,
  and position limits remain.
- The `quantrule-app` application service: workspace, dataset, run validation,
  model run, deterministic export, and local research memory.
- `quantrule.research-memory/v1` over bundled SQLite, with typed CRUD,
  export/import, backup/restore, and deterministic ordering.
- The Tauri 2 + Svelte 5 desktop app in `apps/desktop`: workspace, data, configs,
  model run, memory, export/backup, and settings.
- Linux `QuantRule_0.9.0_amd64.deb` and `.AppImage`, a static `site/` page, and
  SHA-256 checksums.
- Final architecture description, characteristics, methodology checkpoints A–E,
  and nine course PDFs.
- The four-stage board, claim types, execution-plan verification table, and
  mandatory worktree cleanup.

Excluded:

- Accounts, team cloud, sync, subscription, or cloud compute.
- Windows and macOS packaging.
- UI backtest, strategy, execution, portfolio, or analytics orchestration; those
  remain CLI operations.
- A new model, strategy, or portfolio baseline; no edge claim.

## Risks

- The browser E2E uses a fixture backend; the native smoke does not drive the UI.
- The clean install is containerized, not bare-metal Ubuntu.
- The AppImage is 111 MiB and relies on system WebKitGTK/GTK.
- No auto-update, account, team cloud, or cloud backup.
- The UI does not run backtests or analytics; the CLI does.

## Rollback

The previous release is `v0.8.0`, the last pre-Tauri shell release. A rollback is
a checkout of `v0.8.0`; the historical `run/v2` configs are read-only and are not
loaded by the current runner. The research memory is a new local SQLite file, so
no existing data migration is required. A bad published tag is not moved; a new
tag and release note supersede it.
