## Scope

The multi-host deployment release. The six-service server stack can now run
across several Linux hosts from one `quantrule.deploy/v2` descriptor, with the
gateway as the only public service, a private WireGuard/Tailscale overlay, one
image identity, backup/restore, a local multi-host test tier, and a documented
security boundary.

Included:

- `qr-deploy`: descriptor validation, per-service env rendering, and a
  deployed-stack check.
- Per-role Compose files for gateway, core, compute, and infrastructure.
- `QR_INTERNAL_ONLY`, the serve-boundary recheck, and redacted runtime config.
- Multi-host backup/restore wrappers and the local `multi-host` test tier.
- User manual chapter 13 (desktop install), chapter 14 (multi-host), and the
  agent operator runbook.
- The Windows PowerShell browser sequence and the two-machine LAN recipe.
- The `multi-host` architecture, public-boundary, and security documentation.
- Security hardening: public/unspecified hosts, external endpoints, template
  secrets, placeholder digests, IPv6, port zero, Compose bind guards, and
  healthcheck state.
- The accumulated Unreleased history/archive, simulation-bundle, `/ready`, and
  queue-confirmation work recorded in the changelog.

## Risks and rollback

- The profile shares one Postgres role, MinIO root credentials, and queue user
  across services; per-service roles are not implemented.
- The overlay is the service-to-service boundary; a client peer must be routed
  to the gateway only.
- `qr-deploy check` compares the digest a service reports; confirm the running
  image ID with `docker inspect` on each host.
- Postgres, MinIO, and RabbitMQ are single instances; the profile is not high
  availability.
- Rollback is `git checkout v1.3.0` for the client/contracts and the previous
  image digest for the stack. Migrations are forward-only; the multi-host work
  adds no schema migration. Restore from a verified backup if the previous
  binary cannot tolerate the current schema.
