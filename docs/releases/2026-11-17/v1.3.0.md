## Scope

The stage execution surface release. QuantRule runs the model, strategy, and
portfolio engines alone for diagnosis, verifies their artifacts, promotes a
frozen model artifact into a coupled evidence run, records governed improvement
evidence in the v3 ledger, and verifies the deployment from Operations. The
coupled backtest remains the only evidence path; a diagnostic stage is never a
baseline.

Included:

- Diagnostic model, strategy, and portfolio stages with content-addressed
  artifacts, profile scoping, cancellation, deletion, and TTL retention.
- Verified stage artifact download and the Workbench Data, Model, Strategy, and
  Portfolio tabs.
- Promoted `run submit --model-artifact`: the model is reused byte-for-byte;
  strategy, execution, and portfolio are recomputed.
- Research manifest v3, the append-only baseline and invalidation registries,
  the nine research and registry commands, and the Research screen.
- The Operations screen, `GET /operations`, retention and cleanup status, and
  the end-to-end verification tutorial.
- The 12-chapter user manual, command and GUI references, glossary,
  troubleshooting, the manual checker, and the stage-to-backtest tutorial.
- The `1.3.0` version bump and the regenerated model-object oracle and stage
  fixtures. The compiled product version is the only intended model delta.

Deliberately excluded:

- Any model, strategy, execution, portfolio, or signal behavior change beyond
  the compiled version.
- Any edge, profitability, or qualification claim.
- Cross-machine determinism as an observed fact; it remains reviewer-executed.
- A rewrite of the 2026-11-16 course sources or PDFs; they stay the v1.2.0
  snapshot.
- Moving, deleting, or reusing a published tag.

## Risks

- **Unsigned desktop artifacts.** Windows SmartScreen warns, and Linux requires
  the AppImage to be marked executable. There is no code-signing certificate and
  no auto-update.
- **Legacy MinIO stopgap.** The pinned legacy object-store archive is
  amd64-only and unmaintained; the registry decision remains open.
- **Startup-only retention.** Stage cleanup runs at service startup, not on a
  schedule; the Operations snapshot resets on restart.
- **Opt-in Postgres research tests.** They run only with a disposable Postgres;
  the Compose tier exercises Postgres for the service path.
- **Reviewer determinism.** Cross-machine confirmation is reviewer-executed.
  This record claims the local gate, the composed tier, and the canonical digest.
- **No edge claim.** The release ships measurement, diagnosis, and evidence
  plumbing. It makes no claim that any strategy is profitable.

## Rollback

The previous release is `v1.2.0`. This release adds stage, research, and
operations surfaces and a version bump; it does not change model formulas, event
definitions, strategy rules, execution mechanics, portfolio accounting, or policy
thresholds. A code rollback is a checkout of `v1.2.0` plus recovery of the
release records. The server profile rolls back by starting the previous image
digest.

Migrations are forward-only: Postgres `0014`–`0016` and SQLite `0002`–`0004`
add the stage and research tables. A code rollback leaves unused tables and
columns; it does not revert the schema, and the previous version must tolerate
the newer schema. Stage artifacts expire under `QR_STAGE_RETENTION_DAYS`;
runs, research records, and evidence are permanent. A published tag is never
moved; a bad release gets a new tag and a superseding note.
