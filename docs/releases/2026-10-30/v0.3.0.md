## What this release is

v0.3.0 adds the shell and documentation layer around the verified model. It
does not change the model formulas, the strategy, execution, portfolio
accounting, the configuration schemas, or the report schemas.

- **`lab summary`** reads the five report bundles in a lab result folder and
  writes one deterministic `summary.txt` for the whole lab. It never
  recomputes the model.
- **The full-pipeline tutorial** runs the data, model, research, strategy,
  execution, portfolio, store, and lab-summary stages through shell commands,
  with one lab for each quant role.
- **The quant role manuals** give the Quant Researcher, Quant Developer, and
  Quant Validator their own procedures, checks, and handoff packets.
- **The help redesign** makes `help`, `help <command>`, and `help all` render
  from one command table, and adds the glossary, tutorial, and roles topics.

The workspace version and every report's `model_version` move from `0.2.0` to
`0.3.0`. This is a release identity change, not a formula change. A run made
with v0.2.0 and the same input and configuration produces the same values; a new
run records `0.3.0` in its provenance.

## Commands

| Command | Output |
|---|---|
| `lab summary <lab-dir> --role <role> --data-version <id> --config <run.json> --created-utc <ts> [options]` | A deterministic root `summary.txt`; prints `wrote <path>` |
| `help` | A one-screen map of the pipeline, commands, and reference topics |
| `help <command>` | One full command contract; one- or two-word topics such as `store ingest` are accepted |
| `help all` | Every command and option |
| `help glossary` | Precise terms and the contract paths |
| `help tutorial` | The full-pipeline tutorial map |
| `help roles` | The Quant Researcher, Quant Developer, and Quant Validator map |

The existing commands keep their arguments, output, and error behavior.

## Help contract

The output is fixed-width plain text with no terminal-width dependence and no
color. The short map, the command pages, and `help all` render from one command
metadata table, so a command or option cannot be added to one and missed by
another. An unknown topic is an error that points to `help all`.

| Topic | Content |
|---|---|
| `help` | Pipeline, command groups, and reference topics in 43 lines |
| `help <command>` | Usage, summary, options, output, and notes for one command |
| `help all` | Every command page, every option, and the reference topics |
| `help glossary` | NDJSON, report bundle, data version, axes, events, legs, and the contract paths |
| `help tutorial` | The 12-section tutorial map and its repository path |
| `help roles` | The three role manuals, their ownership, and the handoff |

## Configuration and reports

The seven run files, the five report bundles, the 29 bundle artifacts, and the
CSV schemas are unchanged. The lab result folder convention is
`data/lab-result-YYYY-MM-DDTHH-MM-SSZ` in UTC; it holds the five bundles and the
root `summary.txt`. The root summary has seven sections: Identity, Artifacts,
Observed result, Checks, Role notes, Limitations, and Next.

The example run still halts at the configured 20% drawdown limit. That is an
observed result, not a profitability claim and not out-of-sample validation.

## Limitations

- The example backtest is illustrative. It is in-sample only and halts at the
  configured drawdown limit. It is not out-of-sample validation and makes no
  profitability claim.
- The Validator manual and its lab are an exercise, not a production validation
  record. The same engine and machine produce the reproduction.
- The help text is static. It names the tutorial and manuals but does not read
  them; a missing file is not detected by the shell.
