## Scope

This release makes the product version, the current tag, the release records,
the documentation, the course deliverables, and the board name one version:
`1.2.0`. It is a version and record alignment over the 1.1.0 tree. It adds no
model, strategy, execution, portfolio, service, migration, or shell behavior.

Included:

- The workspace, the 16 workspace lockfile entries, the web package, the
  desktop shell, the supervisor, the Tauri config, `SHELL_VERSION`, and the
  desktop version test move to `1.2.0`.
- The model-object regression oracle is regenerated for `1.2.0`: the object is
  66,022 bytes, one byte differs from the `1.1.0` object, and a semantic diff
  reports only `.model_version`.
- The `v1.2.0` release note and changelog section, and the current-tag map
  entries for `v1.1.0` and `v1.2.0`.
- The README, `docs/README.md`, the architecture status index, the deployment
  and user-journey examples, and the release index name `1.2.0` / `v1.2.0`.
- The course methodology and architecture sources name `v1.2.0`, and the
  generated PDFs are rebuilt.
- The release plan and AI transparency log record the two-tag sequence and the
  observed evidence.

Deliberately excluded:

- Any model, strategy, execution, portfolio, service, or migration change.
- Moving, deleting, or reusing a published Git tag.
- A profitability, edge, or cross-machine determinism claim.

## Risks

- **Version bump only.** The canonical pipeline output is unchanged. The only
  model-object delta is the compiled product version; the verification fixture
  digest remains `sha256:453c90b4…`.
- **Unsigned desktop artifacts.** Windows SmartScreen shows "Windows protected
  your PC", and Linux asks the user to mark the AppImage executable. There is no
  code-signing certificate and no auto-update.
- **Object-store stopgap.** The pinned legacy MinIO archive is amd64-only and
  unmaintained; the human registry decision is still open.
- **Reviewer determinism.** Cross-machine confirmation is reviewer-executed;
  this record claims the local gate and the recorded canonical digest.

## Rollback

The previous release is `v1.1.0`. This release changes version declarations,
release records, documentation, and course deliverables, not model formulas,
event definitions, strategy rules, execution mechanics, portfolio accounting, or
policy thresholds. A rollback is a checkout of `v1.1.0` plus the documented
recovery of the release records. The server profile rolls back by starting the
previous image digest; migrations are forward-only, so a rollback never reverts
the schema. A published tag is never moved; a bad release gets a new tag and a
release note that supersedes this one.
