## Scope

This release publishes the existing 1.1.0 tree under the corrected tag
sequence. It is the same six-service server platform and the same
self-contained desktop package as the desktop release, with the release history
normalized so the note filenames, changelog headings, and current tags agree. It
adds no model, strategy, execution, or portfolio behavior.

Included:

- Release-history normalization: the historical note filenames and changelog
  headings now match the current tags, and every renamed note states the
  version it was prepared as.
- The browser client reaches the full shell surface: it inspects candles,
  timeframe ladders, and event batches, verifies a run's recorded digest, and
  downloads an artifact only after its SHA-256 matches the run record. The
  shared parity fixture enumerates all 27 registered commands.
- A composed test tier through `tools/composed.sh`, called by
  `tools/test_tiers.sh composed` and the release workflow.
- `tools/check_client_docs.py` keeps the client screen and store tables, the
  navigation labels, and the 49/150 indicator/event counts aligned with the
  tree and the registry.
- The release workflow validates the current-tag map before it resolves a
  release note, and the desktop supervisor exports a package digest computed
  over the installed sidecars.
- The browser reaches `dataset show` and `config show` through record detail
  views, and a simulation chart exports its rendered SVG.
- The simulation create request and list summary are the `quantrule-api`
  contract types; the service re-exports them without changing the wire shape.
- A profile switch and a disconnection clear every profile-scoped store, so the
  browser does not present a previous profile's data while a new read is
  pending.
- The release image is built and checked locally before any push, and the
  release concurrency key uses the tag name for both a tag push and a manual
  dispatch.
- Worktree cleanup verifies the archive manifest, deletes the archived local
  data, and removes the worktree without `--force`.
- The desktop Continue action opens the gateway that answered the probe, not
  the typed candidate, while the typed URL remains the persisted setting.
- Current runbooks and config contracts name the 27-command gateway surface and
  the run v4 path; the retired policy layer is removed from the Current
  workflows, and the living release/status docs use the current tags.
- The storage, HTTP, control-plane, deployment, operations, and characteristics
  docs match `datasets/`, the evidence-side submission path, the pinned MinIO
  image, the nine-container stack, and the six services.

Deliberately excluded:

- Any new model, strategy, execution, or portfolio baseline, and any
  profitability claim.
- A moved, deleted, or reused historical Git tag. The published tags
  `v0.1.0` through `v1.0.0` are unchanged.
- A second tag for the same commit or a re-tag of the desktop release.
- A maintained object-store registry; the pinned MinIO archive remains a
  stopgap.

## Risks

- **Registry tag reassignment.** The desktop release was published under the
  registry tag `:v1.1.0`; this release reuses that name. The desktop release's
  digest remains pullable and is the stable reference, but a reader who follows
  the mutable tag reaches the 2026-11-16 image.
- **Historical tag commits.** The commits behind `v0.1.0` through `v1.0.0`
  keep their original note filenames and tag lines. The normalized files on
  `main` are the current record; a recovery run for an old tag checks out the
  old tree by design.
- **Unsigned desktop artifacts.** Windows SmartScreen shows "Windows protected
  your PC", and Linux asks the user to mark the AppImage executable. There is no
  code-signing certificate and no auto-update.
- **Object-store stopgap.** The pinned legacy MinIO archive is amd64-only and
  unmaintained; the human registry decision is still open.
- **Reviewer determinism.** Cross-machine confirmation is reviewer-executed;
  this record claims the local gate and the recorded canonical digest.

## Rollback

The previous release is `v1.0.0`. This release changes release records,
documentation, and the browser client, not model formulas, event definitions,
strategy rules, execution mechanics, portfolio accounting, or policy thresholds.
A rollback is a checkout of `v1.0.0` plus the documented recovery of the release
records. The server profile rolls back by starting the previous image digest;
migrations are forward-only, so a rollback never reverts the schema. A published
tag is never moved; a bad release gets a new tag and a release note that
supersedes this one.
