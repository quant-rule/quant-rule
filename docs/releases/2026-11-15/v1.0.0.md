## Scope

The first distributed release. QuantRule is now a single-operator platform whose
work outlives the client: one image digest, six services, nine containers, and
three clients over one `quantrule.api/v1` contract.

Included:

- The server image with six binaries: `qr-gateway`, `qr-data`, `qr-model`,
  `qr-backtest`, `qr-evidence`, and `qr-simulation`, plus the built browser
  client. One published port (`8080`), one bridge network, three named volumes.
- The synchronous data plane (`gateway` → `data` → `model` → `backtest` →
  `evidence`), the asynchronous control plane on RabbitMQ (`runs.backtest`,
  `runs.evidence`, `runs.dead-letter`), and the simulation research plane.
- Per-service schema ownership and migration ledgers: `gateway`, `catalog`,
  `runs`/`research`, `simulation`. The migration runner pins its advisory lock
  to one connection, so the four migrators start together.
- Three clients: the Svelte browser client served by the gateway, the command
  shell (27 commands, one gateway call each), and the Tauri desktop shell with
  no IPC domain and no local data.
- The remote exposure profile: `make remote` publishes only `:8080`, generates or
  reads `QR_BEARER_TOKEN`, and verifies the 401/401/200 token matrix. The shell
  and the browser send `Authorization: Bearer`.
- Profiles as organisational scoping with a gateway-owned profile store; no
  tenant, no account, no multi-tenancy.
- The no-Python and no-Bun image contract: `docker/check-no-python.sh` runs in
  the Dockerfile and in the release workflow; `tools/check_python.py` gates the
  repository.
- Backup and restore over Postgres and the object store, and reviewer
  verification (`make verify`) that submits two equivalent runs through the
  gateway and prints the canonical digest.
- The release pipeline: version tags, the image digest, the Linux AppImage, and
  the Windows NSIS installer; the desktop artifacts are attached to the GitHub
  release.

Deliberately excluded:

- The embedded, self-contained desktop profile (`DIST-200`, v1.1).
- Streaming artifact and candle downloads; v1.0.0 buffers them.
- An app-crate split: the compute services are thin adapters over
  `quantrule-app`; only the gateway is compile-time isolated.
- TLS termination, high availability, and multi-host scheduling; each is a later
  decision.
- A maintained object-store registry: the pinned `bitnamilegacy/minio` archive is
  a stopgap overridable with `QR_OBJECT_STORE_IMAGE` until the human records the
  permanent source.
- Any model, strategy, execution, or portfolio baseline, and any profitability
  claim.

## Release recovery

The tag run failed at the tag check, not at a build. `actions/checkout` fetched
the tag push as `+748355f7…:refs/tags/v1.0.0` with `--no-tags`, which left a
lightweight local ref, so the gate saw a lightweight tag. The workflow now runs
`git fetch --tags --force origin` before `git cat-file -t`, and a genuinely
lightweight tag still fails the gate.

The tag is published and is not moved. Recovery is a manual dispatch of the
existing tag:

```bash
gh workflow run release.yml --ref main -f release_tag=v1.0.0
```

The run checks out `v1.0.0` in every job, repeats the gate, pushes the version
tag to GHCR, rebuilds both desktop artifacts, and creates the release with
`gh release create --verify-tag`. A rerun updates the same release instead of
creating a second one. Once it succeeds, this note's status and digest are
updated if the registry digest differs.

The model-object regression oracle was regenerated for this release: the public
model object carries the compiled product version, and the two objects differ in
exactly that field (66,022 bytes each, two bytes, one semantic path
`.model_version`). No reading, event, or report value changed.

## Risks

- **GHCR permissions.** The workflow pushes with `GITHUB_TOKEN` and job-level
  `packages: write`. The first snapshot under the `quantrule-server` package was
  denied by the registry; the `quantrule-platform` package succeeded and is now
  both the repository variable and the workflow default. The tag run uses the
  same package and permission.
- **Unsigned desktop artifacts.** Windows SmartScreen shows "Windows protected
  your PC", and Linux asks the user to mark the AppImage executable. There is no
  code-signing certificate and no auto-update.
- **Object-store stopgap.** The pinned legacy MinIO archive is amd64-only and
  unmaintained; the human registry decision is still open.
- **Tag immutability.** A bad release gets a new tag, not a moved one. The tag
  build may produce a different manifest digest from the snapshot; the release
  body is authoritative and this note is corrected, not rewritten.
- **Rollback surface.** v1.0.0 is the first container release, so there is no
  earlier image digest to return to. Recovery before the first patch is
  `make reset` and a rebuild from a known commit; the schema is fresh and no
  pre-split database is upgraded.
- **Reviewer determinism.** Cross-machine confirmation is reviewer-executed;
  this record claims only the local two-invocation equality.

## Rollback

Within the 1.0.x line, a rollback is starting the previous image digest.
Migrations are forward-only, so a rollback never reverts the schema and the
previous version must tolerate the newer one. v1.0.0 is the first released
image, so there is no earlier release digest; `make reset` deletes the volumes
and a rebuild from a known commit is the supported path. The desktop shell is a
window over the gateway: reverting it is downloading the previous installer. A
published tag is never moved; a bad release gets a new tag and a release note
that supersedes this one.
