## Scope

v1.1.0 adds the self-contained desktop profile to the v1.0.0 distributed
platform. It is the same six services, the same `quantrule.api/v1` contract,
and the same canonical digest; only the three backend adapters and the packaging
change. The server profile remains the default and the oracle.

Included:

- The desktop profile: SQLite for the four database-owning services, a
  filesystem content-addressed store, and a durable in-process queue, selected
  by `QR_PROFILE=desktop` with `QR_DATA_DIR`. One SQLite file carries state and
  the queue; the server profile keeps Postgres, S3, and RabbitMQ.
- A dependency-free `qr-desktop` supervisor that starts the six sidecars on
  loopback, allocates ports, waits for health, restarts a crashed child, and
  stops them with the shell. A guard ends the children of a crashed supervisor.
- Linux AppImage and Windows NSIS installers built from the same commit. Each
  carries the shell, the supervisor, the six services, the built client, and the
  example configs, and carries no Python or Bun runtime.
- A packaged-profile parity smoke on both operating systems: extract or install
  the artifact, start the six sidecars with a fresh data directory, run the
  verify-mini fixture through the gateway, and require the server canonical
  digest.
- Windows-safe filesystem CAS keys: logical key segments map to portable
  filenames, so a run manifest key containing `sha256:<hex>` no longer fails on
  Windows. The logical key and the byte address are unchanged.
- The v1.0.0 baseline is intact: the server image, six binaries, nine-container
  Compose stack, gateway contract, 27 shell commands, and deterministic pipeline.

Deliberately excluded:

- Code signing, notarization, auto-update, macOS, and MSI packaging.
- Migration between Postgres and SQLite in either direction; the desktop profile
  starts from a fresh data directory.
- New HTTP endpoints, contract versions, routes, or client-specific behavior.
- An in-process engine, a single binary, or fewer than six services.
- A permanent object-store registry; the pinned MinIO archive remains a stopgap.
- Any model, strategy, execution, or portfolio baseline, and any profitability
  claim.

## Risks

- **Unsigned desktop artifacts.** Windows SmartScreen shows "Windows protected
  your PC", and Linux asks the user to mark the AppImage executable. There is no
  code-signing certificate and no auto-update.
- **Object-store stopgap.** The pinned legacy MinIO archive is amd64-only and
  unmaintained; the human registry decision is still open. The desktop profile
  does not use it.
- **Windows path encoding.** The filesystem CAS now maps every logical key
  segment to a portable filename on every platform. A later change to that
  mapping would invalidate the physical layout, so it is part of the storage
  contract rather than an implementation detail; a v1.1.0 data directory is the
  first layout that uses it.
- **First v1.1 tag.** There is no earlier `v1.1` image or installer to roll
  back to. The previous release is `v1.0.0`; its desktop shell is a window with
  no supervisor and does not read the v1.1 data directory.
- **Local SQLite contention.** The queue and the run store share one file. Short
  transactions, WAL, and a busy timeout cover the single-operator case; a slow
  disk is the residual risk.
- **Tag immutability.** A bad release gets a new tag, not a moved one. The tag
  build produced registry digest `sha256:a133ff14…`, which differs from the
  release-preparation local image `sha256:d310f2e9…`; the release body and this
  note record the tag digest. The tag was not moved or recreated.
- **Reviewer determinism.** Cross-machine confirmation is reviewer-executed;
  this record claims the local gate and the recorded packaged runs.

## Rollback

The server profile rolls back by starting the previous image digest
`ghcr.io/quant-rule/quantrule-platform:v1.0.0`. The v1.1.0 server profile adds no
Postgres migration, so no schema step is involved; the forward-only rule still
means a rollback never reverts the schema.

The desktop profile rolls back by reinstalling the previous installer. There is
no earlier packaged desktop release: v1.0.0 shipped only the shell, so removing
the v1.1.0 package is supported and the data directory is preserved but not read
by the v1.0.0 shell. A schema downgrade is refused rather than guessed at. The
desktop backup unit is the data directory — one SQLite database, the CAS tree,
and the supervisor diagnostics — copied while the supervisor is stopped.

A published tag is never moved; a bad release gets a new tag and a release note
that supersedes this one.
