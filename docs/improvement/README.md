This directory is the committed record of improvement runs. A v3 run is a
gateway-reference pre-registration stored in the evidence service: its manifest
is immutable, its pipeline run and canonical digest are linked once after
submission, and its human decision is recorded once. The local
`data/improvement/<YYYY-MM-DD>/<run-id>/` folders, the generated index files, and
the Python run-store tools are historical v2 records. This directory holds the
durable baseline registry, the invalidation tombstones, and the historical v2
templates; it remains human-owned.

The working files under `data/improvement/` (`index.json`, `index.md`) are
historical v2 outputs generated by `tools/improvement/index.py`. When a working
copy and a committed file disagree, the committed file wins and the working copy
is regenerated only for historical reproduction.

## Historical v2 committed summary vs local artifacts

The committed `docs/improvement/<date>/<run-id>-<slug>.md` is the durable v2
record.
It must contain the hypothesis, partition, config path and hash, data version,
the metric table, verdict, limitations, and the local artifact path.

The local `data/improvement/<date>/<run-id>/review.md` and `decision.md` are
working copies produced by `run.py`. They are not a second source of truth. The
heavy artifacts, full event batches, and model CSVs stay local. When a run is
invalidated, its local folder is removed and a row is appended to
[`INVALIDATIONS.md`](INVALIDATIONS.md); the committed summary and the tombstone
remain.

## Current v3 record

A v3 improvement run is one row in `research.improvement_runs`, scoped to the
active profile. The manifest is `quantrule.improvement-run/v3` and carries
gateway references (`data_version`, `config_id`, and a strategy/portfolio
`criteria_id`) rather than filesystem paths. The evidence service validates the
manifest, writes it once, links one pipeline run after submission, records the
canonical digest once when the run produces it, and records one human decision
with a note. An accepted decision needs the digest; a rejected, no-edge,
new-hypothesis, or invalidated decision may be recorded without one.

The committed baseline and invalidation files remain the human-owned source of
truth. The ledger seeds the three accepted model baselines
(`MODEL-2026-11-04-04..05`, `MODEL-2026-11-04-06..07`, and
`MODEL-2026-11-04-10..11`) and the existing tombstones for the `default` profile;
the tables are append-only, so a correction is a new row or a new human decision,
not a rewrite. The evidence service can append a human-accepted baseline or an
invalidation tombstone; a duplicate id is refused and an existing row is never
updated or deleted. A v3 run does not create a local run folder and is never a
stage artifact.

## Historical v2 run record

The v2 contract is historical. It is retained here only to reproduce a pre-v3
record; a new run must not use it. A v2 run folder contains:

```text
data/improvement/<YYYY-MM-DD>/<run-id>/
  manifest.json
  config/
    sources.json
    <run config and sibling JSON files>
  artifacts/
    <shell bundles>
    evidence.json
  results.json
  review.md
  decision.md
```

`manifest.json` is staged before the run and never rewritten. `run.py` creates
the canonical run folder, copies the manifest and config, runs the shell, and
writes `results.json`. `evidence.py` writes `artifacts/evidence.json`.
`review.md` and `decision.md` use the templates below. The index is regenerated
after the decision, not hand-edited.

## Rules

- A v3 run without a valid immutable manifest is not evidence.
- A v3 manifest is created once; the pipeline link and the human decision are
  each recorded once, and a second write is refused.
- Only the human accepts a baseline or records a decision. An agent may
  recommend, never accept.
- `INVALIDATIONS.md` and `research.invalidations` are append-only. Never delete a
  row, even after the artifacts are removed.
- No pre-reset experiment or audit record is imported as a run. The reset has no
  backwards-compatibility layer.
- A baseline is not a live-trading approval; it is the comparison point for the
  next tier.
- The v2 folder, index, and template rules apply only to historical v2
  reproduction; they are not a current run path.
