# QuantRule `quantrule.deploy/v3`

This directory holds the checked-in v3 descriptor, the checked-in Traefik static
configuration, the fake fixture secrets and ingress certificate, and the local
contract examples. The contract is
[`docs/config/2026-11-22/deploy-v3.md`](../../docs/config/2026-11-22/deploy-v3.md);
the supply-chain contract is
[`docs/config/2026-11-24/registry.md`](../../docs/config/2026-11-24/registry.md),
the ingress contract is
[`docs/config/2026-11-23/ingress.md`](../../docs/config/2026-11-23/ingress.md),
the stateful database contract is
[`docs/config/2026-11-23/patroni-cluster.md`](../../docs/config/2026-11-23/patroni-cluster.md),
the object-store contract is
[`docs/config/2026-11-23/minio-cluster.md`](../../docs/config/2026-11-23/minio-cluster.md),
and the reference topologies, sizing, lab preconditions, and pin blockers are
[`docs/config/2026-11-24/reference-topologies.md`](../../docs/config/2026-11-24/reference-topologies.md).

The sample and lab app image is
`ghcr.io/quant-rule/quantrule-platform@sha256:cdace4a996c06cd6142fb63eb23a52136c071d9450fe0e07f5556fc26b9edabe`.
That digest is a **fixture example**, not a published image; `qr-deploy validate
--release` and `qr-deploy check --release` reject it. Write a production
descriptor with `tools/release.sh pin`, sign the digest with the offline cosign
key into a Sigstore bundle plus `cosign save` signed image, and verify it before
`tools/swarm.sh bootstrap` or `upgrade`. `qr-deploy check --remote docker`
compares every running task image, and `--runtime` proves all seven service
digests. Thirteen deployable infrastructure pins (`traefik` through
`blackbox_exporter`) are resolved from registry metadata; the Patroni base is
resolved but the derived pgBackRest image, `minio`, `minio_client`, and the
application image remain exact fixture digests, and `qr-deploy validate --release`
names each one at its field. `cosign.pub.example` documents the public key; the real
`deploy/v3/cosign.pub` is generated by the operator, never committed as a private
key, and `verify` fails closed until it exists.

`qr-deploy` implements the closed schema, version-first dispatch, `validate`,
`validate --files`, `render`, and `check`. The renderer writes the seven-service
Swarm stack, the static and dynamic Traefik files, the per-edge keepalived files,
the per-host Patroni/etcd/HAProxy configuration, the per-node pgBackRest config
and the backup-host script (the sample and both references use an operator-provided off-host S3 primary; the posix path is the documented fallback), the per-broker RabbitMQ config and plugin list, the per-node MinIO config, the app bucket policy and the read-only `qr_archive_reader` policy, the
Prometheus/Alertmanager/Loki/promtail/blackbox/Grafana configuration and four
dashboards, every host's node_exporter/promtail units, the stateful and
observability manifests, the ordered operator jobs, the secret/PKI copies, and
`render.json`. The checker
validates the descriptor, placement, pins, secrets, PKI, and local files and
probes the one HTTPS ingress. `tools/swarm.sh` wraps render, bootstrap, status,
upgrade, rollback, and verify; the control-plane contract is
[`docs/config/2026-11-23/swarm-control.md`](../../docs/config/2026-11-23/swarm-control.md).
`tools/observability.sh` copies, starts, waits, verifies, and stamps the
manager-quorum textfile; its contract is
[`docs/config/2026-11-23/observability.md`](../../docs/config/2026-11-23/observability.md).
`qr-deploy check` adds the stateful rows (Patroni sync/rewind/archive/TLS/
pg_hba/watchdog, etcd mTLS, HAProxy `/primary`, the manifest, and the Postgres/
etcd certificate SANs), the 13 backup rows (stanza, archive commands, no
placeholder, repository, host, off-host boundary, object archive, derived image,
secret absence, script, schedule, unit), and the queue rows (TLS-only broker, three-node cluster,
alarms, HAProxy `rabbitmq`/5671, the broker unit, manifest hosts/modes, and the
RabbitMQ leaf SANs), and the MinIO rows (config/quorum, unit/alias, HAProxy
9000, manifest, app, and leaf SAN/expiry), and the observability rows
(placement, units, 14 jobs/auth, 38 rules/HA matrix, receiver, Loki/promtail,
Grafana, manifest, logging, and internal metrics). `--out <render-dir>` or
`QR_DEPLOY_OUT` reads a rendered
tree; without it the configs render in memory and the certificates come from the
descriptor CA. `--remote docker --overlay` adds the read-only Swarm, node,
overlay, service, port, task, and ingress-mount rows; the default check stays
Docker-free. `tools/test_tiers.sh ha` defaults to `deploy.lab.json` and runs the
opt-in lab in `test.sh`; `--plan` is Docker-free. The harness starts the
observability tier, proves `GatewaySyntheticDown` with a promtool rule unit,
and asserts `SwarmManagerQuorumAtRisk` and `GatewayReplicaDown` fire and
resolve; `--skip-observability` leaves that row `Unverified`. It drains the VIP
holder, pauses the Patroni primary and one HAProxy, stops the RabbitMQ quorum
leader, measures RTO and the queue gap, writes and re-reads markers through
`postgres`, proves a confirmed publish survives the queue loss, compares the
digest/LSN, runs the 8404/5432/8080/9000/5671/15692/15672 negative controls,
records the rejoin, and prints `UNVERIFIED` when a precondition is not met.
`--skip-database`/`--skip-queue`/`--skip-queue-rebuild`/`--skip-object` leave that row `Unverified`; the empty-broker drill is a plan, and `tools/queue-rebuild.sh --plan` prints the import, user, and evidence re-arm sequence.
The MinIO phase writes a probe through `minio:9000`, stops one node, compares
the SHA-256, restores it, runs a bounded `mc admin heal -r`, and waits for zero
healing. The queue and object results are `Simulated HA` at their own level,
and the end-to-end digest is `Measured` only after `tools/verify.sh` succeeds,
otherwise `Unverified` or `Blocked`. The shell
trusts the private CA with `QUANTRULE_CA_CERT`;
the browser uses the OS trust store. v2 output is unchanged.

`deploy/v3/lab.sh` is the lab harness. `--plan` is Docker/SSH/jq/secret-free;
`--reference three-az|single-az|lab` selects the descriptor; `--confirm` gates
the failure phase; `--dr` runs the in-place DR drill after that phase, and
`--skip-dr` leaves the DR row `Unverified`. The preflight runs `qr-deploy validate <descriptor> --release` and stops at
`image.digest`, `images.minio.digest`, `images.minio_client.digest`, or
`images.patroni.digest` with `Unverified` before any host is contacted; there is
no bypass. With a resolved
image it runs stateful `network`/`copy`/`start`/`wait`/`queue-bootstrap`/
`object-bootstrap`, `tools/swarm.sh --allow-unverified bootstrap`, observability
`copy`/`start`/`wait`/`verify`, and `qr-deploy check --remote docker --overlay
--runtime` (7/7). Only the lab descriptor runs `deploy/v3/test.sh --confirm
--skip-deploy`, which remains the failure harness. The remote client phase is
`deploy/v3/lab.sh --remote-client --confirm` on the client
(`QUANTRULE_API_URL`, `QUANTRULE_CA_CERT`, `QUANTRULE_TOKEN`); the browser suite
is `apps/web/playwright.remote.config.ts` (`bun run test:remote`, CA in the OS
store). Evidence is value-free JSON under `QR_LAB_EVIDENCE`; `Simulated HA` is
the maximum and `Real HA` is HA-014.

## Validate, render, check

The sample names `/etc/quantrule/secrets/...` and `/etc/quantrule/pki/ca.crt`,
so a structural check needs no local copies:

```bash
qr-deploy validate deploy/v3/deploy.example.json
```

For the file contract, copy the fixture secrets to a temporary mode-700
directory, make each file mode 600, point a copy of the descriptor at them, and
run `--files`. The test suite does this; the fixture values are not deployable
credentials.

```bash
install -d -m 700 /tmp/qr-v3-secrets
find deploy/v3/secrets -type f ! -name README.md \
  -exec install -m 600 {} /tmp/qr-v3-secrets/ \;
install -d -m 700 /tmp/qr-v3-pki
install -m 644 deploy/v3/pki/ingress.crt /tmp/qr-v3-pki/ingress.crt
install -m 600 deploy/v3/pki/ingress-key.pem /tmp/qr-v3-pki/ingress.key
# point secrets.files, endpoints.*.tls_ca, and ingress.files at the local copies, then:
qr-deploy validate /tmp/deploy.json --files
qr-deploy render /tmp/deploy.json --out /tmp/qr-v3-out --target all
qr-deploy check /tmp/deploy.json --out /tmp/qr-v3-out
```

`--target swarm` writes `stack.yaml`, `quantrule_traefik.yml`,
`traefik-dynamic.yml`, `bootstrap.sh`, `jobs/`, and the shared `secrets/`,
`pki/`, and `render.json`. `--target infra` writes `infra/<host>.yaml`,
`keepalived-<host>.conf`, `patroni-<host>.yml`, `etcd-<host>.conf.yml`,
`haproxy-<host>.cfg`, `rabbitmq-<host>.conf`, `rabbitmq-enabled_plugins`,
`minio-<host>.conf`, `minio-policy.json`, `prometheus.yml`, `alert-rules.yml`,
`alertmanager.yml`, `loki.yml`, `blackbox.yml`, `promtail-<host>.yml`,
`grafana/`, `observability-manifest.json`, and the shared material. `--target all` writes both. A v3 render without `--target` is a
usage error; v2 `render` is unchanged and rejects `--target`.

## Fixture secrets

`secrets/` contains one fake value per required secret: the gateway token, the
four database app/owner URLs, the queue URL, the `qr_app` S3 access/secret pair,
the five stateful Patroni/cluster/RabbitMQ values, the two MinIO root
values (`minio` scope), the pgBackRest passphrase plus S3 pair (`backup`
scope), and the lab's optional read-only `object_archive_reader_secret_key`
(`minio` scope). Every role has a distinct
password, so the duplicate-credential rule can be tested. The stateful values
are URL-safe; `rabbitmq_erlang_cookie` is at least 32 characters. The values are
deliberately non-default but are not real secrets; never deploy them. The
pgBackRest values are read from mode-600 files and never enter a rendered config
or argument.

After the stateful units are up, `tools/stateful.sh queue-bootstrap` creates the
`qr_queue` user, the default vhost, and its permissions from `queue_url`;
`object-bootstrap` creates the `quantrule` bucket, enables versioning, creates
`qr_app`, attaches `quantrule-app`, runs a put/get/delete probe, and (when the
read-only secret is declared) creates `qr_archive_reader` with
`quantrule-archive-reader`. The reader policy allows `s3:GetObject` and
`ListBucket` and no write or delete. The password travels on standard input and is hashed before it reaches
`rabbitmqctl`; it is never an argument or a log line. Run it before
`tools/swarm.sh bootstrap`. `tools/queue-definitions.sh export` stores the
stripped topology (users, permissions, and topic permissions removed) with mode
600 on every broker; `tools/queue-rebuild.sh` imports it into an empty broker,
recreates the user/vhost, and restarts evidence so the run and stage outboxes
re-arm; `verify`, `import`, and 30-day `prune` are in the queue contract.

The empty-broker drill is a lab plan, operator-run: publish a confirmed probe,
recreate the broker with an empty data directory, import the stored definitions,
run `tools/stateful.sh queue-bootstrap`, restart evidence and backtest, then
assert the acknowledged row and probe with one execution and one artifact set.
Inspect `runs.dead-letter.g<n>`; never replay it. `--skip-queue-rebuild` leaves
the row unrecorded. A live drill is `Simulated HA` at most; `Real HA` is HA-014.

## Object archive and DR

`tools/object-archive.sh --plan` prints the one-way archive; `--confirm` copies
new or changed keys from the read-only `qr_archive_reader` source to the
operator-provided target with `mc mirror --overwrite --summary`. There is no
`--remove`, no `--watch`, and no `mc replicate`: it is an archive, not
replication, and the source versioning stays on. The evidence is value-free JSON
with a redacted target identity and a per-key SHA-256 manifest. `--restore`
mirrors the archive into a fresh scratch bucket before rows.

`deploy/v3/dr.sh --plan` prints the scratch or `--in-place` drill. The default
scratch target restores a fresh PGDATA and a fresh object bucket in its own
Compose project; `--in-place` requires `--confirm`, `lab-single-host`, and a
fresh full pre-restore backup, and restores every lab Patroni node with
`pgbackrest restore --delta`. Both rerun the same run/config and compare the
canonical digest; a mismatch fails. RPO is the target minus the newest covered
marker, object RPO is the archive interval, and the RTO is split into restore,
startup, and digest. The three-VM lab is `Simulated HA`; a scratch row is
`Measured` only for the operations run; `Real HA` is HA-014.

`pki/ingress.crt` and `pki/ingress-key.pem` are fake cert-mode fixtures. The
`.pem` name and the absent PEM key block keep the repository private-key checker
honest; the file is not a key and is never used to serve TLS. The sample points
at `/etc/quantrule/pki/...`; point a test copy at the fixtures before running
`--files`.

Git preserves the executable bit, not mode 600. After copying, run the
`install -m 600` command above.

The full shape, field rules, stable `deploy.*` codes, render layout, check
output, profiles, and evidence boundary are in the contract document. The sample
declares eleven hosts, three odd Swarm managers, three compute hosts across
`az1`..`az3`, four infrastructure hosts across `az1`..`az4`, and four MinIO
nodes with one drive each at EC:2; the lab uses three VMs × two drives at EC:3.
The reference descriptors in `reference/` reuse the eleven host names:
`three-az.json` (`swarm-ha`) spreads four racks over three AZs with the edge pair
on one L2/AZ, and `single-az.json` (`single-az`) keeps four racks in one AZ. The
lab template uses `10.10.0.11..13`, VIP `10.10.0.20`, public addresses
`10.10.0.11/12`, one `lab` failure domain, and three managers; `/etc/hosts`, the
private CA, the operator certificate, and the firewall are preconditions. It has
etcd, HAProxy, and keepalived blocks and a non-empty `secrets.files` map, a VIP,
and a cert-mode ingress. The stack uses `/health` checks, stop-first when no
spare slot exists, and a 180 s update monitor; the bootstrap creates both Traefik
configs before `docker stack deploy` and refuses secret/config drift.
